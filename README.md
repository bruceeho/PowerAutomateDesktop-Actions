## 🎯 這個工具的用途

Power Automate Desktop（PAD）的流程在設計工具裡只能拖拉，但每個動作其實都對應一行 **Robin 代碼**，
可以 `Ctrl+C` / `Ctrl+V` 在設計工具和文字之間互轉。這個專案就是把這些代碼整理成一個**可以直接複製貼上的動作庫**：

| 用途 | 說明 |
|---|---|
| 📚 **查動作寫法** | 每個 PAD 動作一個 txt，打開就能看到完整語法和參數，不用在設計工具裡一個個拖出來看。 |
| ✍️ **用文字寫流程** | 把需要的動作複製出來、填好參數，組成完整流程後一次貼進 PAD。 |
| 🤖 **搭配 Claude 開發** | Claude 讀得懂這些文字檔，可以照需求文件直接產出能貼進 PAD 的流程程式碼（見[用 Claude 處理這些檔案](#-用-claude-處理這些檔案)）。 |
| ✅ **累積實測規則** | 把「哪些寫法貼得進去、哪些會失敗」的實測結果記下來，避免重複踩雷。 |

## 📁 資料夾結構

```text
PowerAutomateDesktop_動作\
├─ 動作\        每個 PAD 動作一個 txt：動作\<模組>\<分類>\<動作名稱>\<動作名稱>.txt
├─ 流程\        使用這個專案時，實際要貼進 PAD 的流程程式碼（每個專案一個子資料夾）
├─ 需求文件\    流程的相關文件：需求、規格、代碼表、截圖等，寫流程時拿來對照
├─ _工具\       產生、更新、比對動作庫的 PowerShell 腳本
└─ 動作總表.csv 所有動作的一覽表
```

### 動作\

- 每個 txt 只有可直接貼進 PAD 設計工具（`Ctrl+V`）的 Robin 代碼，**沒有額外註解**。
- 有多種模式的動作（例如「啟動 Excel」）每種模式各一行，以空行分隔，**只複製需要的那一行**。
- ` `` ` 代表需要自己填的值：文字用 `$'''內容'''` 包起來，變數直接寫變數名稱。

### 流程\

放使用這個專案時實際要貼進 PAD 的流程程式碼，整段貼上即可。範例：

- [台銀匯率存成Excel.txt](<流程/台銀匯率存成Excel.txt>)：用「從網頁擷取資料」，含錯誤處理與執行記錄
- [台銀匯率爬取.txt](<流程/台銀匯率爬取/台銀匯率爬取.txt>)：用「在網頁上執行 JavaScript」，已確認可貼上

### 需求文件\

放流程的相關文件（需求、規格、代碼表、截圖等），寫流程時拿來對照，也可以請 Claude 讀取後列出缺少的資訊。

## 📋 貼上規則（2026-11-10 實測）

> [!WARNING]
> 只要有**一行** PAD 解析不了，**整段都不會貼上，而且不會顯示任何錯誤**。
> 遇到這種情況，把代碼分段貼上，找出是哪一行出問題。

- `$'''...'''` 文字裡避免使用：單引號 `'`、`<`、`>`、`||`、`%`
  - `%` 會被當成變數，例如 `%DesktopPath%`；真的要用時才寫
  - `\` 要寫成 `\\`，例如 `$'''%DesktopPath%\\檔名.xlsx'''`
  - `"` 可以用，照 PAD 自己的寫法寫成 `\"` 最保險
- 在 JavaScript 裡：
  - 字串一律用雙引號
  - 用 `forEach` 取代 `for (i < n)` 迴圈
  - 用 `if (!x) { x = ... }` 取代 `x || y`
  - 換行用 `String.fromCharCode(10)`，不要寫 `\n`
- 已在本機 PAD 確認可貼上的語法：
  `# 註解`、`SET x TO ...`、`LOOP i FROM 1 TO 15 STEP 1`、`WAIT 2`、`IF x <> $'''''' THEN ... END`、`EXIT LOOP`、`EXIT Code: 0`
  （`# 註解` PAD 支援，但本專案慣例不使用，見[程式碼風格](#-程式碼風格)）
- 單獨貼上一段時，變數尚未定義而出現紅色錯誤是正常的，整段流程貼完就會消失。

## 🔧 實測校正（2026-11-11）

拿「流程」資料夾裡能執行的流程比對動作庫，修正了以下問題：

| 項目 | 正確寫法 |
|---|---|
| 如果… 類動作（如果檔案已存在、如果網頁包含、如果影像、如果視窗…） | `IF (WebAutomation.IfWebPageContains.WebPageContainsElement ...) THEN` … `END` |
| 等待… 類動作（等待網頁內容、等候檔案、等待處理序、等待視窗…） | `WAIT (WebAutomation.WaitForWebPageContent.WebPageToContainElement ...) FOR 10` |
| 動作名稱多了 `Action`（例如 `IfWebPageContainsAction`） | 貼上會變成未知動作，已改掉 |
| 取代文字 | 只保留實測可用的 `Text.Replace.ReplaceTextWithRegex`（一般文字也能用） |
| 修剪文字、填補文字、顯示訊息 | 補上 `Text`、`PaddingText`、`Title`、`Message` 參數 |

- 要確認動作庫是否還有對不上的地方：執行 `_工具\比對實測動作.ps1`，
  會列出「流程」資料夾實際用到、但動作庫找不到或參數不同的寫法，並存成 `_工具\比對結果.csv`。
- 動作名稱以**實際能執行的流程為準**；參數名稱和選項可以參考動作庫。
- 有些參數是選填的，動作庫裡不會列出（例如 `MatchMode`、`CommandLineArguments`），需要時自行加上。

## 🧩 UI 元素（元素庫）規則（2026-11-11 實測）

> [!IMPORTANT]
> 瀏覽器動作範本的 `Control: ``` 要填元素庫引用，**單引號一律寫成 `\'`**，少一個反斜線整段都貼不進去：
> ```text
> appmask['Web Page \'https://example.com/Page.aspx\'']['Input submit \'送出\'']
> ```

- 程式碼後面接 `# [ControlRepository][PowerAutomateDesktop]` 和元素庫 JSON，可以**整份一起貼上**，元素會自動加進 UI 元素窗格，不用重新錄製。元素名稱要和程式碼引用完全一致。
- 選取器要用變數（例如表格每列不同的 `ctl%RowNo%`）時，必須用**自訂選取器**（選取器編輯器的文字編輯器模式）：
  ```text
  input[Id="ctl00_ContentPlaceHolder1_gv02_ctl%RowNo%_txtQty"]
  ```
  只在屬性值裡寫 `%變數%` 不會被代換，執行時會出現「找不到具有選取器…」。元素庫 JSON 裡對應的是 `"IsCustom": true` 和 `"CustomSelector": "..."`。
- 貼到已經有同名元素的流程時，只貼程式碼（開頭到 `# [ControlRepository]` 的前一行），避免元素重複。
- 不同網頁的元素 Id 可能不同，即使畫面相似也要各自錄製或核對選取器。
- 整份檔案的換行要一致（**全部 CRLF**），混用 LF 會貼不進去。
- 程式碼裡 `CALL` 到的子流程（例如 `CALL 'Error'`），要先在流程裡建好同名子流程。
- 雲端連線參照（`ConnectionReferences`，例如 SharePoint）不影響貼上。
- 元素庫裡的截圖路徑（`ScreenshotPath`）是否影響貼上尚未單獨驗證；貼不進去時可先把它設成 `null` 再試。

## 🎨 程式碼風格

- `動作\` 的 txt 只放代碼，不加任何說明。
- `流程\` 的程式碼**不加 `#` 註解**；需要說明時用區域包住段落：
  ```text
  **REGION 說明文字
  ...
  **ENDREGION
  ```
  區域可以巢狀，但不能跨越 `IF`、`LOOP`、`BLOCK` 的開頭或結尾。
- `@@` 開頭的行是雲端連接器的中繼資料，不是註解，要保留。
- 整份檔案一律 **CRLF 換行、UTF-8 編碼**。

## 🤖 用 Claude 處理這些檔案

在 Claude 桌面版的 **Code** 分頁，把工作資料夾設成這個專案資料夾（`PowerAutomateDesktop_動作`），再用下面的 prompt 開頭。

**🆕 寫新流程**

```text
我要寫 PAD 流程：<要做什麼>，相關文件在 需求文件\<檔名>。
請先讀 README.md；動作寫法以 流程\ 裡實際能執行的流程為準，參數參考 動作\。
產出可直接貼進 PAD 的完整程式碼檔（含元素庫），放在 流程\<專案名稱>\，
照 README 的程式碼風格：不加 # 註解、用 **REGION 說明、全部 CRLF、元素引用的單引號寫成 \'。
```

**✏️ 修改既有流程**

```text
請修改 流程\<專案名稱>\<檔名>.txt 的 <哪一段>，另存成新檔，原檔不要動。
```

**🔍 先看需求缺什麼**

```text
請讀 需求文件\<檔名>，對照 流程\<專案名稱>\ 現有程式，列出還缺少或不明確的資訊。
```

- 需要網頁欄位 Id 時：在 Claude 的**內建瀏覽器**打開該頁並自行登入，再請 Claude 讀取（只讀不點）。
- 貼不進 PAD 時：把錯誤訊息或截圖給 Claude，或請它把程式碼拆成幾段分批貼，找出出問題的那一行。

> [!CAUTION]
> 帳號密碼由使用者自己輸入，**不要寫進 prompt 或程式碼**。

## 🛠️ 工具腳本（`_工具\`）

| 腳本 | 用途 |
|---|---|
| `更新動作清單.ps1` | **PAD 更新後執行這個。** 依序呼叫下面兩支，只新增缺少的動作，不覆寫既有檔案。 |
| `擷取動作.ps1` | 從本機 PAD 安裝目錄的模組 DLL 讀出所有動作與參數，存成 JSON。 |
| `產生動作檔.ps1` | 依 JSON 產生 `動作\` 底下的 txt 與 `動作總表.csv`；重建總表時會保留 SharePoint 等雲端連接器的列。 |
| `比對實測動作.ps1` | 比對 `流程\` 實際用到的寫法與動作庫，結果存成 `比對結果.csv`。 |

```powershell
powershell -ExecutionPolicy Bypass -File ".\_工具\更新動作清單.ps1"
```
