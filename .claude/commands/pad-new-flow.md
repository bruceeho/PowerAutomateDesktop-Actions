使用者想寫一個新的 PAD 流程：$ARGUMENTS

照下面步驟進行，**資訊不足時不要直接寫程式**。

## 1. 先讀資料

- 讀 `README.md` 的貼上規則、UI 元素規則、程式碼風格。
- 看 `需求文件\` 有沒有相關文件；有的話先讀。
- 看 `正式流程\`、`demo\` 有沒有類似的流程可以參考寫法。

## 2. 確認以下資訊，缺的一次列出來問使用者

用編號清單問，每一項說明為什麼需要。已經從文件或對話中知道的就不要再問。

1. **目的與觸發方式**：手動執行、排程，還是由 SharePoint／其他流程呼叫？輸入變數有哪些（名稱與範例值）？
2. **要操作的系統**：網站網址或桌面程式名稱、使用哪個瀏覽器（Chrome／Edge）、需不需要登入。
3. **輸入資料**：資料從哪裡來（Excel、SharePoint、網頁、資料夾）、欄位有哪些，最好附一份範例檔。
4. **操作步驟**：逐步描述或需求文件的哪個部分；每一步要點什麼、填什麼。
5. **輸出結果**：結果寫到哪裡、什麼格式、檔名與路徑規則。
6. **例外處理**：找不到資料、網頁沒回應、登入失敗時要怎麼做？要通知誰、SharePoint 狀態要寫什麼？
7. **網頁元素**：是否已有錄好的 UI 元素或流程可沿用？沒有的話需要使用者在內建瀏覽器開頁面讓 Claude 讀欄位 Id（見 `/pad-get-element-ids`）。
8. **相依的子流程**：會不會 `CALL` 其他子流程（例如 `Error`）？這些子流程是否已存在？
9. **測試方式**：有沒有可以安全測試的資料？哪些按鈕在測試時不能真的按（送出、回覆、刪除）？
10. **執行環境**：在哪台電腦執行、OneDrive／共用資料夾的實際路徑。

## 3. 確認方向

資訊足夠後，先用 5–10 行說明流程架構（子流程切分、主要步驟、資料怎麼流），請使用者確認後再寫程式。

## 4. 產出

- 放在 `正式流程\<專案名稱>\`，檔名用子流程名稱。
- 依 `README.md` 的程式碼風格：不加 `#` 註解、用 `**REGION` 說明、全部 CRLF、元素引用的單引號寫成 `\'`。
- 需要 UI 元素時，程式碼後面接 `# [ControlRepository][PowerAutomateDesktop]` 與元素庫 JSON；選取器含變數時用自訂選取器。
- 產出後自我檢查：換行是否全為 CRLF、元素引用是否都在元素庫中、`CALL` 的子流程是否都存在。
- 最後告訴使用者：要貼到哪個子流程、測試時要注意什麼、哪些部分是假設或還沒驗證。
