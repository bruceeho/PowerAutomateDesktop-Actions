使用者想修改既有流程：$ARGUMENTS

## 1. 先讀

- 讀 `README.md` 的規則與程式碼風格。
- 讀要修改的流程檔，以及它 `CALL` 到或被呼叫的相關子流程（同一個 `流程\<專案名稱>\` 資料夾）。
- 確認這份檔案目前是否能正常執行（問使用者），避免在壞掉的版本上改。

## 2. 確認以下資訊，缺的一次列出來問使用者

1. **要改的範圍**：哪個子流程、哪一段（可用 REGION 名稱或行為描述）。
2. **改完的預期結果**：輸入什麼、應該得到什麼；有沒有可測試的範例資料。
3. **影響範圍**：改動會不會影響其他子流程讀寫的資料（例如 Excel 欄位順序、變數名稱）。
4. **新的網頁欄位或元素**：需要的話，請使用者提供欄位 Id 或用內建瀏覽器讓 Claude 讀取。
5. **要保留的既有行為**：哪些寫法雖然看起來奇怪但是故意的（例如固定等待、重試次數），不要順手改掉。

## 3. 修改

- 另存成新檔（例如 `<原檔名>_New.txt`），原檔不要動。
- 只改使用者要求的部分；發現其他問題列在回覆裡，不要自行修改。
- 依程式碼風格：不加 `#` 註解、用 `**REGION` 說明、全部 CRLF、元素引用的單引號寫成 `\'`。
- 用 Python 等腳本寫檔，寫完檢查：CRLF、元素引用都在元素庫中、IF/LOOP/BLOCK 與 END 數量相符。

## 4. 回覆

- 用程式碼片段說明改了什麼、為什麼這樣改。
- 說明怎麼貼（整份或只貼程式碼）、測試時要注意什麼、哪些部分還沒驗證。
